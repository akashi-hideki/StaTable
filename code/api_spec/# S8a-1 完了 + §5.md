## 1. `validator.py` 分析

### 1.1 構造

```python
class CodeGenerationValidator:
    VALIDATORS: Dict[str, Type] = {...}  # 11カテゴリ
```

**SPEC_OVERVIEW_en.md には検証APIの記載が皆無**。全て本S8aで新規追加。

### 1.3 実行モデル

```
CodeGenerationValidator.validate(sm, gd)
  ├── ValidationContext(sm, gd) を生成
  ├── result = ValidationResult()
  └── for category, validator in self._validators.items():
        ├── try:
        │     issues = validator.validate(context)
        │     result.issues.extend(issues)
        └── except Exception as e:
              logger.error(...)   # ← 失敗しても続行
```

**重要**：**バリデータ単位で例外を捕捉**。1つのバリデータがクラッシュしても全体は続行。これは `BaseValidator` の B-02（例外処理なし）を上位層で補償している。

### 1.4 `BaseValidator` の B-02 制限への対応

S8a-1途中で指摘した「`rule_func` の例外処理なし」は、`CodeGenerationValidator.validate()` の try/except で**カテゴリ単位に補償**される。ただし：

- `rule_func` 個別の失敗は、**同じカテゴリ内の後続ルールもスキップ**される（`validator.validate()` 全体が中断）
- つまり「1ルールの失敗 = 同カテゴリ全ルール結果喪失」

### 1.5 検証済みの事項

| 項目 | 結果 |
|------|------|
| 依存関係 | `models.py`, `logger.py`, `items/*` のみ。**外部SDK依存なし** |
| バリデータ数 | **11**（SPEC_OVERVIEWには未記載） |
| 例外処理 | カテゴリ単位で try/except |
| 拡張性 | `VALIDATORS` 辞書を差し替え可能（サブクラス化） |
| 実行順序 | `VALIDATORS` の挿入順（辞書順） |

## 2. §5.1 検証API 章ドラフト

### 5.1 `CodeGenerationValidator`

コード生成前の一貫性検証を統括するエントリポイント。

#### 5.1.1 クラス定数

| 定数 | 型 | 説明 |
|------|-----|------|
| `VALIDATORS` | `Dict[str, Type]` | カテゴリ名 → バリデータクラス（11エントリ） |

**`VALIDATORS` の内容**

| キー | クラス | モジュール |
|------|--------|-----------|
| `'state'` | `StateValidator` | `items/state_validator.py` |
| `'event'` | `EventValidator` | `items/event_validator.py` |
| `'transition'` | `TransitionValidator` | `items/transition_validator.py` |
| `'role_function'` | `RoleFunctionValidator` | `items/role_function_validator.py` |
| `'variable'` | `VariableValidator` | `items/variable_validator.py` |
| `'flag'` | `FlagValidator` | `items/flag_validator.py` |
| `'queue'` | `QueueValidator` | `items/queue_validator.py` |
| `'interrupt'` | `InterruptValidator` | `items/interrupt_validator.py` |
| `'timer'` | `TimerValidator` | `items/timer_validator.py` |
| `'custom_type'` | `CustomTypeValidator` | `items/custom_type_validator.py` |
| `'cell'` | `CellValidator` | `items/cell_validator.py` |

**拡張方法**：サブクラスで `VALIDATORS` を上書き、または `_validators` に追加。

#### 5.1.2 `__init__`

```python
def __init__(self) -> None
```

**動作**：`VALIDATORS` の各エントリを**インスタンス化**して `self._validators` に格納。

**属性（非公開）**

| 名前 | 型 | 説明 |
|------|-----|------|
| `_validators` | `Dict[str, BaseValidator]` | カテゴリ名 → バリデータインスタンス |

#### 5.1.3 `validate`

全カテゴリの検証を実行し、統合結果を返す。

```python
def validate(
    self,
    state_machine: StateMachine,
    global_defs: GlobalDefinitions,
) -> ValidationResult
```

**パラメータ**

| 名前 | 型 | 必須 | 説明 |
|------|-----|------|------|
| `state_machine` | `StateMachine` | ○ | 対象ステートマシン |
| `global_defs` | `GlobalDefinitions` | ○ | グローバル定義 |

**戻り値**：`ValidationResult` — 全カテゴリの課題を統合

**動作**

1. `ValidationContext(state_machine, global_defs)` を生成
2. `ValidationResult()` を初期化
3. `self._validators` を挿入順で走査：
   - `validator.validate(context)` を呼び出し
   - 返された `issues` を `result.issues` に追加
   - **例外発生時は `logger.error` でログ後、次のバリデータへ続行**
4. 統合 `ValidationResult` を返す

**例外**

なし（内部で全例外を捕捉。バリデータ単位の失敗は結果に含まれない）

**使用例**

```python
from codegen.validate.validator import CodeGenerationValidator

validator = CodeGenerationValidator()
result = validator.validate(sm, gd)

if result.passed:
    print("Validation passed")
else:
    for issue in result.get_errors():
        print(f"[{issue.category}] {issue.code}: {issue.message}")
```

#### 5.1.4 `validate_category`

単一カテゴリのみを検証する。

```python
def validate_category(
    self,
    category: str,
    state_machine: StateMachine,
    global_defs: GlobalDefinitions,

```

**パラメータ**

| 名前 | 型 | 必須 | 説明 |
|------|-----|------|------|
| `category` | `str` | ○ | カテゴリ名（`VALIDATORS` のキー） |
| `state_machine` | `StateMachine` | ○ | 対象SM |
| `global_defs` | `GlobalDefinitions` | ○ | グローバル定義 |

**戻り値**：`List[ValidationIssue]` — 該当カテゴリの課題。未知カテゴリは `[]`。

**例外**

なし（未知カテゴリは `logger.warning` のみ）

#### 5.1.5 `get_categories`

```python
def get_categories(self) -> List[str]
```

**戻り値**：`List[str]` — 登録カテゴリ名一覧（11件）

**使用例**

```python

# ['state', 'event', 'transition', 'role_function', 'variable',
#  'flag', 'queue', 'interrupt', 'timer', 'custom_type', 'cell']
```

## 4. U-13 最終判断：検証API の SDK 公開範囲

### 4.1 結論

**§5 検証API を SDK 公開APIに含める。ただし以下の注記を付す。**

### 4.2 判断理由

| # | 理由 |
|---|------|
| 1 | **外部依存なし**：`models.py` + `items/*` + `logger.py` のみ。`statable_gui` への依存なし |
| 2 | **拡張点として設計**：`VALIDATORS` 辞書の差し替え、`BaseValidator` のサブクラス化で独自バリデータ追加が可能 |
| 3 | **ツールベンダー関心事**：生成コードの品質保証はSDK利用者が自前で組み込む必要がある |
| 4 | **既にリファレンス実装あり**：`statable_gui/validation_dialog.py` が統合例を提供（S8bで詳細化） |
| 5 | **データモデルが純粋dataclass**：`to_dict` / `from_dict` でシリアライズ可能 |

### 4.3 公開する範囲

| 項目 | 公開 | 理由 |
|------|------|------|
| `CodeGenerationValidator` | ○ | エントリポイント |
| `ValidationResult` / `ValidationIssue` / `ValidationSeverity` / `ValidationContext` | ○ | データモデル |
| `BaseValidator` | ○ | 独自バリデータ作成の基底 |
| 11個の個別バリデータ | **△** | 「参考実装」として掲載。SDK利用者は通常 `CodeGenerationValidator` 経由で使用 |
| `AIPromptGenerator` / `AIResponseParser` | ○（S8a-3で判断） | AI診断連携 |
| `ChangeApplier` / `ChangeRequest` | ○（S8a-3で判断） | 変更適用 |
| `ClipboardManager` | △（S8a-3で判断） | 補助 |
| `validation_dialog.py` | **×** | GUI依存（S8bで扱う） |

### 4.4 公開上の注意事項

| # | 注意 |
|---|------|
| N-01 | バリデータは**例外を投げない設計**（内部で捕捉）。ただし結果に失敗が現れない点を明記 |
| N-02 | `BaseValidator.rules` は**クラス属性ミュータブル**。サブクラスで `rules = {...}` と**再定義**すること（`update` 禁止） |
| N-03 | カテゴリ実行順は `VALIDATORS` の挿入順。順序依存のルール設計は避けること |
| N-04 | `ValidationContext` は `cell_actions` / `cell_relations` のプロキシ未実装。CellValidator が SM 直接アクセス |
| N-05 | `validate_category` は例外捕捉なし（未知カテゴリは空リスト）。個別実行時のエラーは呼び出し側責任 |
