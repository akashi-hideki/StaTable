## 2. 分析：実装パターンの2系統

### 2.1 パターンA（10ファイル）：`validate()` オーバーライド + `_create_issue`

`state`, `event`, `transition`, `role_function`, `variable`, `flag`, `queue`, `interrupt`, `timer`, `custom_type` が該当。

**構造**：

```python
class XxxValidator(BaseValidator):
    category = "xxx"

    def __init__(self):
        self.rules_data = VALIDATION_RULES.get(self.category, {})
        self.rules = {
            'XXX_CODE_1': self._check_1,
            'XXX_CODE_2': self._check_2,
        }

    def validate(self, context):
        issues = []
        for code, rule_func in self.rules.items():
            try:
                result = rule_func(context)
                if result:
                    issues.extend(result)
            except Exception as e:
                logger.error(f"Rule '{code}' failed: {e}", exc_info=True)
        return issues

    def _create_issue(self, code, **kwargs):
        rule = self.rules_data.get(code, {})
        message = rule.get('message', '').format(**kwargs)
        severity = ValidationSeverity.from_string(rule.get('severity', 'info'))
        return ValidationIssue(
            category=self.category, code=code, message=message,
            severity=severity, suggestion=rule.get('suggestion', ''),
            target=kwargs.get('name', ''),
        )
```

**特徴**：
- `VALIDATION_RULES` から**メッセージ・重大度・提案**を取得
- **ルール単位の try/except**（`BaseValidator.validate()` をオーバーライド）
- `_create_issue(code, **kwargs)` で `str.format` によるメッセージ生成

### 2.2 パターンB（1ファイル）：`cell_validator` のみ

**構造**：

```python
class CellValidator(BaseValidator):
    category = "cell"

    def __init__(self):
        self.rules_data = VALIDATION_RULES.get(self.category, {})
        self.rules = {
            "CELL_EMPTY_CONDITION": self._rule_empty_condition,
            ...
        }

    # validate() をオーバーライドしない → BaseValidator.validate() を使用
    # （ルール単位の try/except なし）

    def _severity(self, code):   # VALIDATION_RULES から severity のみ取得
        ...

    def _make_issue(self, code, message, target=""):
        # メッセージはハードコード、severity のみ VALIDATION_RULES から
        ...
```

**特徴**：
- **`validate()` 非オーバーライド** → `BaseValidator.validate()` を継承（**ルール例外は上位層で捕捉**）
- **`_make_issue(code, message, target)`** — メッセージを呼び出し側で組み立て
- **`_iter_cells(context)`** ヘルパーで v2.2 cell metadata を列挙
- **動的メッセージ**（`f"Transition '{label}' ..."`）

### 2.3 パターンの不整合（重要）

| 項目 | パターンA（10） | パターンB（cell） |
|------|----------------|------------------|
| `validate()` オーバーライド | ○ | × |
| ルール単位 try/except | ○ | ×（上位層任せ） |
| メッセージ生成 | `VALIDATION_RULES` テンプレート | ハードコード |
| `suggestion` フィールド | `VALIDATION_RULES` から設定 | **未設定**（常に空） |
| ヘルパー名 | `_create_issue` | `_make_issue` |
| `VALIDATION_RULES` の利用 | message / severity / suggestion | severity のみ |

**→ §9 制限事項に「CellValidator は設計が異なる」旨を追記候補**

### 5.3.2 `StateValidator`（4ルール）

| ルールコード | チェック内容 |
|-------------|-------------|
| `STATE_NO_INITIAL` | `initial_state` が None |
| `STATE_UNREACHABLE` | 遷移先に現れず初期状態でもない |
| `STATE_NO_TRANSITION` | 遷移元に現れない |
| `STATE_DUPLICATE` | 大文字小文字を無視した重複 |

### 5.3.3 `EventValidator`（2ルール）

| ルールコード | チェック内容 |
|-------------|-------------|
| `EVENT_UNUSED` | どの遷移でも使われないイベント |
| `EVENT_NO_TRANSITION` | 関連遷移のないイベント |

**備考**：`EVENT_UNUSED` と `EVENT_NO_TRANSITION` は**意味が重複**（`used_events` と `has_transition` は同条件）。実質1ルール相当。

### 5.3.4 `TransitionValidator`（5ルール）

| ルールコード | チェック内容 |
|-------------|-------------|
| `TRANSITION_TARGET_UNDEFINED` | `target` が未定義状態 |
| `TRANSITION_EVENT_UNDEFINED` | `event` が未定義 |
| `TRANSITION_SOURCE_UNDEFINED` | `source` が未定義 |
| `TRANSITION_DUPLICATE` | `(source, event, target)` の重複 |
| `TRANSITION_SELF_LOOP` | `source == target` |

**`_create_issue` の拡張**：`target` 引数で `target / source / event` の優先順位を処理。

### 5.3.5 `RoleFunctionValidator`（3ルール）

| ルールコード | チェック内容 |
|-------------|-------------|
| `ROLE_FUNC_NO_RETURN_TYPE` | `return_type` が空 |
| `ROLE_FUNC_ARG_MISMATCH` | `arg1_type` と `arg1_name` の不整合 |
| `ROLE_FUNC_UNUSED` | 遷移の `action` / `condition` から参照されない |

**注意**：`ROLE_FUNC_UNUSED` は `t.action` と `t.condition` の**文字列完全一致**のみチェック。`RoleFunc_*` 形式や条件式内の関数呼び出しは未検出（S8bでテストから確認要）。

### 5.3.6 `VariableValidator`（3ルール）

| ルールコード | チェック内容 |
|-------------|-------------|
| `VAR_DUPLICATE_NAME` | 変数名重複 |
| `VAR_INVALID_TYPE` | 基本型・カスタム型以外 |
| `VAR_INVALID_ARRAY_SIZE` | `array_size < 0` |

**`VAR_INVALID_TYPE` の基本型リスト**：`int/int8/.../uint64/float/double/bool/char/string/void`

### 5.3.12 `CellValidator`（8ルール、v2.2）

| ルールコード | 重要度 | チェック内容 |
|-------------|--------|-------------|
| `CELL_EMPTY_CONDITION` | Warning | condition も target も空 |
| `CELL_DUPLICATE_LABEL` | Error | セル内 label 重複 |
| `CELL_DANGLING_RELATION` | Error | relation が存在しない label 参照 |
| `CELL_UNREACHABLE_TRANSITION` | Warning | Commit+else の後続遷移 |
| `CELL_OVERLAP_POSSIBLE` | Warning | 同一 condition 文字列の重複 |
| `CELL_DUPLICATE_TARGET` | Info | 複数遷移が同一 target |
| `CELL_EXCLUSIVE_NO_RETURN` | Info | exclusive member に early_return なし |
| `CELL_EMPTY_TARGET` | Warning | target 空 + early_return=False |

**v2.2 特有のAPI使用**：
- `sm.get_cell_keys()` で cell metadata 列挙
- `sm.get_transitions_for_cell(source, event)` / `sm.get_relations_for_cell(source, event)`
- `Transition.label` / `TransitionRelation.members` / `.kind`

**重要度は `VALIDATION_RULES` から取得**（ハードコードではない）。
