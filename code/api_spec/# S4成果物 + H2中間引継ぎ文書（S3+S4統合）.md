### 4.6.4 ロール関数呼び出しの3形式（SPEC_OVERVIEW §7.4.5 の核心）

| メソッド | 用途 | 出力 |
|---------|------|------|
| `_role_func_call_expr` | **条件式**（`Transition.condition` 等） | `RoleFunc_X(transition, ctx)` |

| `_role_func_call` | デフォルト（=action） | `(void)RoleFunc_X(transition, ctx)` |

**MISRA 17.7準拠**のための分岐。

### 4.6.5 Cell関数の `_handled` パターン

`early_return=True` の遷移が**2個以上**あるセルのみ `_handled` を宣言。

```c
bool _handled = false;
...
if ((!_handled) && (cond1)) { ... _handled = true; }
else if ((!_handled) && (!(cond1))) { ... _handled = true; }
```

`early_return=True` が1個以下の場合、`_handled` は宣言されない（MISRA 15.7 抑制の根拠）。

### 4.6.6 GetNextEventのMISRA 17.3対応（v2.6）

`LOG_ERROR` 呼び出しを**削除**してコメントに置換：

```c
if (consecutive_count > MAX_CONSECUTIVE_PENDING_EVENTS) {
    /* Pending event chain too long: force reset */
    ctx->pending_event_valid = false;
    ...
}
```

cppcheck が可変引数マクロ `LOG_ERROR` を展開できない問題への対処。

### 4.7.2 `SUPER_LOOP_TEMPLATES['run_block']`（v2.2.5 gcc compile fix）

**v2.2.5以前**：全レイヤが `EVENT_<Layer>_t evt` を同一スコープで宣言 → gcc で `conflicting types for 'evt'` エラー。

**v2.2.5以降**：各レイヤを `{ ... }` でスコープ化：

```c
while (1) {
    {
        EVENT_Application_t evt = StateMachine_GetNextEvent_Application(&g_ctx);
        if (evt != EVENT_Application_NONE) {
            g_Application_state = StateMachine_Process_Application(g_Application_state, evt, &g_ctx);
        }
    }
    {
        EVENT_Driver_t evt = StateMachine_GetNextEvent_Driver(&g_ctx);
        ...
    }
}
```
