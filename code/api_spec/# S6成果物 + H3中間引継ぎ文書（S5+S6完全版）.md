## 4.8.2 `CTypeMapper`（`type_mapper.py`）

StaTable型 → C型のマッピング。**全メソッドが classmethod**。

### クラス定数

| 定数 | 説明 |
|------|------|
| `TYPE_MAPPING` | StaTable型 → C型（`int32` → `int32_t` 等、16エントリ） |
| `TYPE_CATEGORIES` | 型 → カテゴリ（integer / float / boolean / character / string / void） |
| `HEADER_REQUIREMENTS` | カテゴリ → 必要ヘッダ（`integer` → `#include <stdint.h>` 等） |

### メソッド（全て classmethod）

| メソッド | シグネチャ | 戻り値 |
|---------|-----------|--------|
| `map_type` | `(sta_type: str) -> str` | C型名。未登録はそのまま |
| `get_type_category` | `(sta_type: str) -> str` | カテゴリ。未登録は `'custom'` |
| `get_required_headers` | `(types: List[str]) -> List[str]` | 必要ヘッダ（ソート済み） |

### 型マッピング表（抜粋）

| StaTable型 | C型 | カテゴリ |
|-----------|-----|---------|
| `int8` | `int8_t` | integer |
| `int32` | `int32_t` | integer |
| `uint8` | `uint8_t` | integer |
| `uint32` | `uint32_t` | integer |
| `float` | `float` | float |
| `bool` | `bool` | boolean |
| `string` | `char*` | string |

### 使用例

```python
from codegen.type_mapper import CTypeMapper

CTypeMapper.map_type("uint32")           # → "uint32_t"
CTypeMapper.get_type_category("uint32")  # → "integer"
CTypeMapper.get_required_headers(["uint32", "bool"])
# → ["#include <stdbool.h>", "#include <stdint.h>"]
```

## 4.8.3 `CNamingConvention`（`naming_convention.py`）

C命名規則。**全メソッドが classmethod**。**v2.2.5**。

### クラス定数

| 定数 | 説明 |
|------|------|
| `CONVERSION_PATTERNS` | 変換パターン（upper_snake / lower_snake / camel / pascal） |
| `C_KEYWORDS` | C予約語（35語） |
| `IDENTIFIER_RULES` | 種別 → 変換メソッド名（variable / function / type / enum / macro） |

### 基本変換メソッド（classmethod）

| メソッド | シグネチャ | 例 |
|---------|-----------|-----|
| `to_snake_case` | `(name, upper=False) -> str` | – |
| `to_upper_snake` | `(name) -> str` | `"myEvent"` → `"MY_EVENT"` |
| `to_lower_snake` | `(name) -> str` | `"MyEvent"` → `"my_event"` |
| `to_camel_case` | `(name) -> str` | `"my_event"` → `"myEvent"` |
| `to_pascal_case` | `(name) -> str` | `"my_event"` → `"MyEvent"` |
| `sanitize_identifier` | `(name) -> str` | 予約語に `_` 付与、記号を `_` に |
| `create_identifier` | `(name, kind='variable') -> str` | 種別に応じた変換 |
| `create_type_name` | `(name) -> str` | 冪等（後述） |
| `create_enum_value` | `(prefix, name) -> str` | – |
| `create_function_name` | `(module, action) -> str` | – |
| `create_variable_name` | `(name) -> str` | – |
| `create_macro_name` | `(name) -> str` | – |

### `create_type_name` の冪等性（v2.2.5）

```python
CNamingConvention.create_type_name("SystemStatus")     # → "SystemStatus_t"
CNamingConvention.create_type_name("SystemStatus_t")   # → "SystemStatus_t"  （変化なし）
CNamingConvention.create_type_name("sensor_data")      # → "SensorData_t"
CNamingConvention.create_type_name("sensor_data_t")    # → "sensor_data_t"   （変化なし）
CNamingConvention.create_type_name("")                 # → "Unknown_t"
```

**修正理由**：旧実装では `SystemStatus_t` → `SystemStatusT_t` に二重化していた。

### 使用例

```python
from codegen.naming_convention import CNamingConvention

CNamingConvention.to_pascal_case("driver_init")        # → "DriverInit"
CNamingConvention.to_upper_snake("myEvent")            # → "MY_EVENT"
CNamingConvention.sanitize_identifier("int")           # → "int_"  （予約語回避）
CNamingConvention.create_type_name("SystemStatus")     # → "SystemStatus_t"
```

# Part C: §7 マーカー方式マージ仕様

## 7.1 概要

StaTable は生成コードに**マーカーコメント**を埋め込み、再生成時にユーザが追記したコードを保持する。

**マーカー方式の利点**：
- 生成コードとユーザコードの境界が明確
- 再生成時に自動マージ可能
- 生成ファイルをそのままバージョン管理可能

## 7.2 マーカー一覧（8種）

| # | マーカー | 用途 | 配置 |
|---|---------|------|------|
| 1 | `[[STABLE_USER_CODE_START]]` / `END` | ファイル先頭ユーザ領域 | include直後 |
| 2 | `[[STABLE_USER_CODE_START:<name>]]` / `END:<name>` | 関数内ユーザ領域 | 各ロール関数/ISR内 |
| 3 | `[[STABLE_USER_CODE_TAIL_START]]` / `END` | ファイル末尾ユーザ領域 | ファイル末尾 |
| 4 | `[[STABLE_AUTO_GENERATED_START]]` / `END` | 自動生成領域（予約） | – |

## 7.3 マーカー命名規則

### 関数内マーカー（`<name>` の決定）

| 関数種別 | 命名 | 例 |
|---------|------|-----|
| `RoleFunc_<NS>_<Name>` | `<NS>_<Name>` | `RoleFunc_Driver_Init` → マーカー `Driver_Init` |
| `RoleFunc_<Name>`（NS無） | `<Name>` | `RoleFunc_Init` → マーカー `Init` |
| `ISR_<Name>` | `<Name>`（レイヤ無） | `ISR_TIMER0` → マーカー `TIMER0` |

### 抽出時の正規表現

```python
FUNC_NAME_PATTERNS = [
    r'RoleFunc_(\w+)\s*\(',   # RoleFunc_Driver_Init( → "Driver_Init"
    r'ISR_(\w+)\s*\(',        # ISR_TIMER0(        → "TIMER0"
]
```

## 7.4 マージ動作（`merge_file`）

### 7.4.1 処理フロー

```
merge_file(generated_content, existing_content)
  ├── existing_content が None/空 → generated をそのまま返す
  ├── 1. ユーザコード抽出
  │   ├── extract_file_user_code()
  │   ├── extract_all_func_user_codes()
  │   └── extract_file_tail_user_code()
  ├── 2. 生成コードに注入
  │   ├── inject_file_user_code()
  │   ├── inject_func_user_code()  ← 各関数
  │   └── inject_file_tail_user_code()
  └── 3. マージ済みコードを返す
```

### 7.4.2 `inject_file_user_code` の動作（v2.0修正）

**v2.0以前の問題**：既存ブロックがある場合でも、include直後に**新規ブロックを挿入**していた → 旧ブロックがデッドコード化。

**v2.0以降**：
1. 既存ブロックがあれば**内容のみ置換**（`re.subn` で `count=1`）
2. 既存ブロックがなければ、include直後に新規挿入

```python
# 既存ブロック置換
pattern = rf'({re.escape(start)}\s*\n).*?(\n\s*{re.escape(end)})'
replacement = rf'\g<1>{user_code}\n\g<2>'
result, count = re.subn(pattern, replacement, content, count=1, flags=re.DOTALL)
```

### 7.4.3 `inject_func_user_code` の動作

- 生成コードに**マーカーが存在する前提**で、内容のみ置換
- マーカーがなければ**何もしない**（警告ログのみ）
- 新規挿入は行わない（マーカーは生成側が必ず出力する）

### 7.4.4 `inject_file_tail_user_code` の動作

- 末尾マーカーの内容を置換
- マーカーがなければ**何もしない**（警告ログのみ）

## 7.5 フォルダ構成対応（`merge_all_files`）

```python
def merge_all_files(
    self,
    generated_files: Dict[str, str],
    existing_dir: str,
    path_resolver: Optional[Callable] = None,
    layer_name: str = '',
) -> Dict[str, str]
```

| パラメータ | 型 | 説明 |
|-----------|-----|------|
| `generated_files` | `Dict[str, str]` | ファイル名 → 生成コード |
| `existing_dir` | `str` | 既存ファイル検索のベースディレクトリ |
| `path_resolver` | `Callable \| None` | `(filename, layer_name) -> rel_path` |
| `layer_name` | `str` | レイヤ名（`by_layer` 用） |

**`path_resolver` の役割**：`by_layer` 等のフォルダ構成でファイルパスを解決。`CCodeGenerator._resolve_output_path` が渡される。

## 7.6 使用例

### 7.6.1 単一ファイルのマージ

```python
from codegen.code_merger import CodeMerger

merger = CodeMerger()

generated = "... /* [[STABLE_USER_CODE_START:Driver_Init]] */\n..."
existing  = open("statable_role_functions.c").read()

merged = merger.merge_file(generated, existing)
```

### 7.6.2 全ファイルマージ（`CCodeGenerator` 経由）

```python
from codegen.c_code_generator import CCodeGenerator
from codegen.config import CodeGenerationConfig

config = CodeGenerationConfig(save_with_merge=True, output_directory="./output")
gen = CCodeGenerator(config=config)

files = gen.generate_all_layers(layers, global_defs)
saved = gen.save_generated_code_with_merge(files, "./output")
```

### 7.6.3 ユーザコード量の集計

```python
summary = merger.get_user_code_summary(existing_content)
# {
#     'file_user_code': 123,       # ファイル先頭ユーザ領域の文字数
#     'func_user_codes': 5,        # 関数内ユーザ領域を持つ関数数
#     'file_tail_user_code': 456,  # ファイル末尾ユーザ領域の文字数
# }
```
