# Part B: §4.7 内部サブジェネレータ章ドラフト

## 4.7.1 位置づけ

**§4.7 は「内部サブジェネレータ」として扱い、SDK の安定公開 API には含めない**（U-10の結論、Part C参照）。ただし、`CCodeGenerator` の内部構造を理解するための**参考情報**として掲載する。

各ジェネレータは `CCodeGenerator.__init__` でインスタンス化され、step-table driven で呼び出される。

| 4 | `EventQueueGenerator` | `event_queue_generator.py` | – | イベントキュー |

## 4.7.2 `CStructGenerator`（`struct_generator.py`）

構造体生成。**v2.2.1** でセクションヘッダの C ブロックコメント化。

### クラス定数（公開）

| 定数 | 説明 |
|------|------|
| `CONTEXT_TEMPLATES` | `SystemContext_t` テンプレート |
| `MACRO_TEMPLATES` | `FIRE_EVENT` / `MAX_CONSECUTIVE_PENDING_EVENTS` |
| `COMMON_TRANSITION_CONTEXT_TEMPLATES` | 共通 `TransitionContext_t` |
| `LAYER_TRANSITION_CONTEXT_TEMPLATES` | レイヤ別 `TransitionContext_<Layer>_t` |
| `MEMBER_TYPE_DETECTORS` | メンバ型判定（bit_field / array / normal） |
| `MEMBER_TEMPLATES` | メンバ生成テンプレート |

### 公開メソッド

| メソッド | シグネチャ | 戻り値 |
|---------|-----------|--------|
| `set_layer` | `(layer_name: str) -> None` | – |
| `generate_struct` | `(struct_type: str, item) -> str` | 単一構造体（後方互換） |
| `generate_all_structs` | `(global_defs: GlobalDefinitions) -> str` | 全構造体（custom + system系） |
| `generate_common_transition_context` | `() -> str` | 共通 `TransitionContext_t` |
| `generate_layer_transition_context` | `(state_type, event_type) -> str` | レイヤ別 `TransitionContext_<Layer>_t` |
| `generate_pending_event_macros` | `() -> str` | `FIRE_EVENT` / `MAX_CONSECUTIVE_*` |
| `generate_all` | `(global_defs) -> Dict[str, str]` | 全生成物辞書（6キー） |

### 生成される構造体

1. `CustomTypeDef` 群（ユーザ定義型）
2. `SystemData_t`（グローバル変数）
3. `EventFlags_t`（イベントフラグ）
4. `SystemContext_t`（**`pending_event` / `pending_event_valid` を v2.2 で追加**）
5. `TransitionContext_t`（共通ベース型）
6. `TransitionContext_<Layer>_t`（レイヤ別）
7. `FIRE_EVENT` / `MAX_CONSECUTIVE_PENDING_EVENTS` マクロ

# Part C: U-10 の結論（SDK公開判断）

## 結論：**§4.7 の7クラスは SDK 安定公開 API に含めない（内部実装扱い）**

### 理由

| # | 理由 |
|---|------|
| 1 | **`CCodeGenerator` 経由でのみ呼ばれる**設計。SDK利用者が直接使う想定がない |
| 2 | 各ジェネレータは `GlobalDefinitions` 等の内部型に強く依存し、単独利用が困難 |
| 3 | `generate_struct` の**後方互換API**（`CStructGenerator.generate_struct(struct_type, item)`）など、歴史的経緯のAPIが混在 |
| 4 | `TimerGenerator.generate_struct` が**空文字列を返す**など、内部リファクタリングの影響が公開APIに漏れる |
| 5 | ツールベンダーが必要とするのは **`CCodeGenerator` + `CodeGenerationConfig` + `CodeTemplates`** の3点で十分 |

### ただし、以下は公開APIとして残す

| クラス | 公開範囲 | 理由 |
|--------|---------|------|
| `CodeTemplates` | **公開**（§4.6） | テンプレート辞書はサブクラス化によるカスタマイズを想定 |
| `CCodeGenerator.file_generators` / `FILE_STEPS` 等のクラス定数 | **公開** | 生成ファイル一覧の取得に必要 |

### §4.7 の記述方針

- **「内部サブジェネレータ（Internal Sub-generators）」** として掲載
- 各クラスの **公開メソッドは列挙するが、「非公開API」と明記**
- SDK利用者は `CCodeGenerator` 経由でのみ使用すること
- `CodeTemplates` のみ「カスタマイズ可能」として §4.6 で詳細化済み
