## 2. 開発したソフトウェア「StaTable」の概要

- **名称**: StaTable
- **内容**: 組込みシステム向けの汎用状態機械設計ツール。
  MISRA C:2012に準拠したCコードを自動生成する。
- **特徴**: 七層アーキテクチャ、表駆動型コード生成、
  ユーザーコード保護、Eclipse統合、QEMU検証済み。
- **ライセンス**: Apache License 2.0
- **公開状況**: PyPIおよびGitHubにて公開中（v3.5.3）。
  中国語ドキュメントも整備済み。
- **開発形態**: 個人の時間・個人の機材（個人PC、個人ネットワーク）
  を用いて開発。会社の機材・ネットワーク・ノウハウは一切使用していない。
- **開発期間**: 2026年8月13日～2026年10月11日（Git履歴参照）

## 3. 現職会社の事業内容と StaTable の関係

### 3.1 事業レイヤーの違い

現職会社の事業と StaTable は、**「組込み」というキーワードを
共有しますが、事業レイヤーが根本的に異なります。**

| レイヤー | 現職会社 | StaTable |
|---|---|---|
| アプリケーション層 | ✅ 電源装置の制御ソフト | ❌ 該当しない |
| ミドルウェア層 | ❌ 該当しない | ❌ 該当しない |
| 開発ツール層 | ❌ 該当しない | ✅ ここに該当 |

### 3.2 「使用」と「開発」の区別

| 観点 | 現職会社 | StaTable |
|---|---|---|
| 組込みソフトの立場 | 製品を動かすために**使用** | 開発するための**ツール** |
| 事業上の位置づけ | 自社製品の制御 | 他社の開発支援 |
| 顧客 | 半導体・液晶メーカー | 組込みエンジニア全般 |
| 競合 | 他の電源装置メーカー | IAR、Qt、Vector など |

### 3.3 結論

現職会社は「組込みソフトを使う側」、StaTable は
「組込みソフトを作る側を支援するツール」であり、
**事業領域は重複せず、競合関係にもありません。**

## 4. 相談事項

### 4.1 就業規則との関係

現職会社の就業規則には「起業は許さない、従事は許さない」との
文言があると理解しています。
本件開発行為および将来の売却行為が、同規定に違反するか否かに
ついてご教示ください。

特に、以下の点を明確にしたいと考えています:
- 事業内容が異なる場合でも「起業」に該当するか
- 無償OSS公開と有償売却の違い
- 現状の活動（無償公開）の適法性

### 4.2 職務発明該当性

StaTable の技術領域は現職会社の事業内容とは異なりますが、
それでも職務発明に該当すると主張されるリスクはあるでしょうか。
また、それを回避するために事前に取り得る措置はありますか。

### 4.3 前職A（ルネサス）および元中国企業との関係

前職Aおよび元中国企業との間で、競業避止義務や秘密保持義務が
存在する可能性があります。
特に、元中国企業との関係において、中国企業への売却が
契約違反とならないか懸念しています。
契約書の確認方法、および注意すべき点についてご教示ください。

### 4.4 著作権の帰属と証明

StaTable の著作権が相談者に帰属することを証明するために、
どのような資料が必要でしょうか。
現在、Git履歴、タイムスタンプ（RFC 3161）、
OSSコンプライアンス宣言書、技術白書などを準備しています。
これらで十分か、追加で必要なものがあればご教示ください。

### 4.5 中国企業への売却・ライセンス

中国企業への売却またはライセンス供与を検討しています。
その際の法的留意点、契約上の注意事項、中国商標の出願方法に
ついてご教示ください。
また、外国人が中国で商標出願する場合の代理機関の選定に
ついてもご相談したいです。

### 4.6 OSSライセンスの確認

StaTable のコアは依存関係ゼロであり、GUIオプションで
PySide6（LGPL）を使用しています。
この構成での商用配布・売却に問題がないか、最終確認をお願いします。
