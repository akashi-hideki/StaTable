# 最終詳細仕様書

## 1. 概要

StaTable は、組み込みエンジニアが普段使い慣れている **状態遷移表（マトリックス形式）** をGUIで作成・編集し、以下の成果物を自動生成するデスクトップアプリケーションです。

- **Mermaid状態遷移図**（オフラインで即時プレビュー）
- **PlantUML / XMI**（無料UMLツール用）
- **Cソースコード**（状態遷移配列 / Dictionary形式 / switch文）
- **テストケース**（全状態・全遷移・N-switchカバレッジ）

状態遷移表を中心に、設計・実装・テストまでを一気通貫で支援します。

## 3. 主要機能

### 3.1 状態遷移表エディタ（マトリックス形式）

- 行＝状態（フルパス表記）
- 列＝イベント名（空列は完了遷移）
- セル＝ `次状態 [C言語式ガード] / 動作`
- セル編集時にC言語式の構文チェック・変数/状態/イベントの補完を行う。
- 行・列の追加/削除/並べ替え、セル色付け、コメントをサポート。

**例：**

| 状態＼イベント | start | stop | error | 完了 |
|---|---|---|---|---|
| Idle | Active / init(); | - | - | - |
| Active | - | Idle / stop(); | Error [err_code != 0] / log(); | - |
| Error | - | - | - | Active [retry_count < 3] / retry_count++; |

### 3.2 状態定義（階層・並行対応）

状態はフルパスで管理し、**リージョン名を状態名に埋め込む方式**で並行状態を表現する。

| 項目 | 内容 |
|---|---|
| 状態名 | フルパス（例：`System::Sensor::Idle`） |
| type | `normal` / `concurrent` / `region` / `initial` / `final` / `choice` / `junction` |
| entry / exit / do | C言語文または関数呼び出し |

- `concurrent` 状態の直下には必ず `region` を置く。
- `region` は状態ではなくコンテナであり、entry/exit/doを持たない。
- リージョン番号ではなく、`System::Sensor`、`System::Motor` のように意味のある名前で区別する。

**状態定義例：**

| 状態名 | type |
|---|---|
| System | concurrent |
| System::Sensor | region |
| System::Sensor::Idle | normal |
| System::Sensor::Active | normal |
| System::Motor | region |
| System::Motor::Stopped | normal |
| System::Motor::Running | normal |

### 3.3 イベント辞書

イベントを一元管理する辞書機能。状態遷移表の列ヘッダーはこの辞書から選択する。

| 項目 | 必須 | 説明 |
|---|---|---|
| イベント名 | ● | 一意の名前 |
| ID |  | 数値ID（省略時は自動採番） |
| 種類 |  | `signal` / `call` / `time` / `change` |
| パラメータ |  | C言語型で記述（例：`uint8_t err_code`） |
| 優先度 |  | RTOS等で使用 |
| 説明 |  | メモ |

- 完了遷移は `EVENT_NONE` として自動定義。
- イベント辞書からイベントenum、イベント構造体をコード生成に反映。

### 3.4 変数定義

- ツール内で変数を管理。
- **外部Cヘッダファイル（.h）を取り込み可能**。
  - 変数・定数・enum・関数プロトタイプを抽出。
  - ガード式の補完・構文チェックに使用。

### 3.5 ガード条件（C言語式）

- C言語の条件式として解釈。
- 使用可能：算術・比較・論理・ビット演算子、括弧、変数、純粋関数。
- 禁止：代入、インクリメント/デクリメント、カンマ演算子、副作用のある関数。
- 入力時に構文チェックを実施。

## 4. コード生成

### 4.1 Cコード生成

以下の3形式から選択可能。

#### (1) 状態遷移配列（配列形式）
```c
typedef struct {
    state_t current_state;
    event_t event;
    bool (*guard)(void);
    void (*action)(void);
    state_t next_state;
} transition_t;

const transition_t transition_table[] = {
    { STATE_IDLE, EVENT_START, NULL, action_init, STATE_ACTIVE },
    // ...
};
```

#### (2) Dictionary形式（2次元配列直接索引）
```c
const transition_entry_t transition_table[STATE_NUM][EVENT_NUM] = {
    [STATE_IDLE] = {
        { STATE_ACTIVE, NULL, action_init }, // EVENT_START
        // ...
    },
};
```

#### (3) switch文
```c
switch (current_state) {
case STATE_IDLE:
    if (event == EVENT_START) { action_init(); return STATE_ACTIVE; }
    break;
    // ...
}
```

**共通生成物：**
- 状態enum（`state_t`）
- イベントenum（`event_t`、`EVENT_NONE`含む）
- ガード関数（C言語式から自動生成）
- アクション関数（動作文から自動生成）
- パラメータ付きイベント用のイベントデータ構造体

**オプション：**
- プレフィックス指定、ヘッダ分割（.c/.h）、コメント出力、配列探索方法（線形/二分）

### 4.2 テストケース生成

以下のカバレッジ基準に対応。

| 基準 | 説明 |
|---|---|
| 全状態網羅 | 全状態を通過 |
| 全遷移網羅 | 全遷移を実行 |
| N-switchカバレッジ | 連続N回の遷移列を網羅 |
| 全イベント網羅 | 各状態から全イベントを試行（不正遷移含む） |

出力形式：CSV、Unity、CppUTest、Google Test  
- パラメータ付きイベントは設定値を含める。
- ガード条件を満たすセットアップを自動生成可能。

## 6. 検証機能

### エラー
- 未定義の状態・イベント・変数
- 同一「現状態＋イベント＋ガード」の重複遷移
- 不正なC言語式ガード
- 並行状態のリージョン定義矛盾
- 初期状態の重複・欠落

### 警告
- 到達不能状態
- デッドロック可能性（特定イベントの遷移先なし）
- 未使用の状態・イベント・変数
- 状態爆発の可能性（並行状態の直積数が大きい）

---

## 7. 入出力・プロジェクト管理

- プロジェクトはJSON/YAMLで保存。Git差分が容易。
- 既存Excel/CSVのインポート（列マッピングGUI）。
- 状態遷移表・状態定義・イベント辞書・変数定義をすべてプロジェクトに含む。
- インポート/エクスポートプラグインの追加が可能。

## 8. 非機能要件
